# PathSnap map matching

Match noisy GPS points to the road network. Pipeline:

1. generate candidate road arcs for every GPS point and build features (`data_processing/`, `features/`)
2. score the candidates with an ML classifier (`models/`, tuned with Optuna in `hpo/`)
3. run an HMM with Viterbi over the scores to get one connected route (`hmm/`)
4. serve it from a FastAPI backend on Laptop 1 (`api/`) with a Streamlit UI on Laptop 2 (`ui/`)

## Install

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Data

The trips are **not** in the repo (no raw data is committed). Put them in `data/` (so that `data/train/<id>/`
and `data/student_test/<id>/` exist) or point to them with `PATHSNAP_DATA`:

```bash
export PATHSNAP_DATA="/path/to/Student folder/Student folder"      # Windows: $env:PATHSNAP_DATA="..."
```

Each trip folder holds `<id>.track` (lon, lat, t), `<id>.nodes` (lon, lat; row = node id),
`<id>.arcs` (from_node, to_node; row = arc id) and `<id>.route` (ground-truth arc ids in order).
The data covers the whole world, so distances are measured in metres in a per-trip local projection
(`data_processing/load.py: LocalProjector`), never in degrees.

## Reproduce everything (in this order)

```bash
python features/build_features.py        # ~1.5 min: candidates + labels + features -> results/*.parquet, candidate_miss_rate.csv
python features/ablation_v1_v2.py        # feature v1 vs v2 -> results/feature_v2_ablation.csv
python data_processing/eda_plots.py      # EDA figures -> results/eda/
jupyter nbconvert --to notebook --execute --inplace data_processing/eda.ipynb   # EDA notebook (+ Folium map)

python models/train_all.py               # 6 models, 5-fold GroupKFold CV -> results/model_comparison.csv, cv_folds.csv, confusion_matrices.json
python models/select_final.py            # final-model selection rule -> results/model_selection.csv
python hpo/optuna_search.py              # Optuna TPE -> results/hpo_trials.csv, hpo_plots/, hpo_tuned_vs_untuned.csv, artifacts/model.pkl
python visualisations/model_plots.py     # comparison plots -> results/plots/

python hmm/tune_hmm.py                   # decoder parameters (train + student_test only) -> artifacts/hmm_config.json
python hmm/evaluate_hmm.py               # classifier-only vs classifier+HMM -> results/hmm_comparison.csv, results/maps/*.html

python report/capture_screenshots.py     # UI / API-console / Folium screenshots -> results/screenshots/
python report/build_report.py            # technical report PDF -> report/PathSnap_Report.pdf
```

The parquet files in `results/` and the per-model files in `artifacts/all_models/` are gitignored and regenerated by
the commands above. `artifacts/model.pkl`, `feature_config.json` and `hmm_config.json` are committed.
`random_state=42` is used everywhere. The evaluator trips are never used for training, tuning or threshold choice.

## Layout

```
data_processing/  loader + projection, labels, EDA notebook and figures
features/         candidate generation, feature table, v1-vs-v2 ablation
models/           metrics, training harness, final-model selection, predict_scores()
hpo/              Bayesian tuning with Optuna
hmm/              road graph, Viterbi, pipeline (run_trip), HMM tuning and evaluation
api/  ui/         FastAPI backend, Streamlit UI
visualisations/   Folium maps, model comparison plots
results/          CSVs, logs, plots, maps       artifacts/  model + configs       report/  report builder
```

## API (Laptop 1)

```bash
# EVAL_DIR holds the trip folders; the evaluator trips are dropped into it on the day
EVAL_DIR="path/to/student_test" uvicorn api.main:app --host 0.0.0.0 --port 8000
```

* `GET /trips` trip ids found in `EVAL_DIR` (re-scanned on every call)
* `POST /predict {"trip_id": "..."}` GPS points, the predicted route (connected polylines), the classifier-only route
  and accuracy metrics computed on the server
* `GET /health` backend and model info

The model is loaded once at startup. Accuracy is computed on the server from the trip's own `.route`; ground-truth
arcs are never returned. Every request is logged to the console (trip id, timing, Top-1, continuity). Set
`PATHSNAP_BACKEND=stub` for placeholder responses (network tests only).

## UI (Laptop 2)

```bash
streamlit run ui/app.py
```

Enter the API URL in the sidebar, pick one of the trips, press **Run**. The map shows the GPS points, the HMM route (red)
and the classifier-only route (orange); the cards show Top-1, route continuity and inference time.

## Two-laptop setup

1. Put both laptops on the same Wi-Fi or hotspot.
2. Laptop 1 (API): allow port 8000 through the Windows firewall
   (`netsh advfirewall firewall add rule name="PathSnap API" dir=in action=allow protocol=TCP localport=8000`,
   in an administrator terminal), find the IP with `ipconfig`, start the API as above.
3. Laptop 2 (UI): check `curl http://<laptop1-ip>:8000/trips`, then `streamlit run ui/app.py` and set the API URL
   to `http://<laptop1-ip>:8000`.

## Final dry run

1. `python models/train_all.py` and `python hpo/optuna_search.py`; confirm the CSVs appear in `results/`.
2. `python hmm/evaluate_hmm.py`; confirm `results/hmm_comparison.csv`.
3. Laptop 1: `uvicorn api.main:app --host 0.0.0.0 --port 8000` with `EVAL_DIR` pointing at the trips.
4. Laptop 2: run all 10 trips in the UI; check that the map and metrics appear and that Laptop 1 logs every request.
5. Clone the repo fresh and follow this README from scratch.
